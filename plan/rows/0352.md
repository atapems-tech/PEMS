## Evidence

The application has no database export or import of its own data (only the Import Center for Excel files and the Database Update page for schema). Demo and staging need a repeatable way to capture and restore their data.

## Prompt

Design first (ADR): logical export of every user table to a package (.pemsdata, zip) with a manifest: format version, product version, last applied migration, schema fingerprint, per-table row counts and SHA-256, package hash; import = precheck (hash, format, schema compatibility) then replace. Admin UI page for the proper role/permission only; the same page links to the Import Center for Excel imports. Disabled by setting outside demo/staging unless the owner enables it. Audit every export and import.

## Requirement

Done when: an authorised administrator exports a package from the UI and re-imports it into an empty or existing database of the same version; a tampered or incompatible package is rejected with the reason; every action is audited; tests cover precheck, hash, round trip and the permission.
