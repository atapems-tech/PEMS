## Evidence

Owner question 2026-10-27: how does the administrator get the first random password in the UI? Today the administrator comes from Seed__Admin__Password in the secrets file; nothing shows a generated password, and after a database reset the first-install flow must restart. 2026-10-27 owner decision: instead of generating, storing and revealing a random one-time password, the administrator sets the password in the UI as the last install step (no secret to generate or store, replaces the forced first change, uses the policy and the history rule of #382). This is the administrator step of the first-run wizard #169.

## Prompt

1) Condition: user table empty and no Seed__Admin__Password. Every request goes to /setup (static page) until done; staging and demo keep Seed__Admin__Password and skip it; an update never reaches it. 2) Guard against first-comer takeover: a one-time setup code written to a file next to the application and logged as a pointer only; /setup asks for it (optionally also server/management network only); rate limited; code and file deleted when the administrator exists; /setup is 404 afterwards. 3) Step: user name, e-mail, password (policy and history apply), confirm, sign in; MustChangePassword=false; the install is complete; licence/TLS/MFA steps of #169 attach to the same frame later. 4) After a database reset the page appears again with a new code. 5) Attempts go to Security Events (no password, no code). Two modes, decided only by whether Seed__Admin__Password is set: not set -> the administrator chooses the password on /setup, install complete, no forced change; set from an env/secrets file (staging, demo) -> the administrator is created from it and the first sign-in forces a change (MustChangePassword=true, history rule applies). An administrator password is never part of a client build.

## Requirement

Done when: fresh install, database reset and local first run show /setup and nothing else until the administrator exists; the setup code is required and removed afterwards; the chosen password follows the policy; /setup is 404 once an administrator exists and after an update; staging/demo with Seed__Admin__Password skip it; tests, README check, guideline and runbooks updated. Setup mode leaves MustChangePassword=false; seeded mode sets it true and the first change cannot keep the seed password.
