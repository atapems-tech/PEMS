## Evidence

Static audit 2026-10-29 found 174 catch (Exception), 36 bare catch, 131 generic throw new Exception(, 89 user-visible ex.Message, 4 Task.Run fire-and-forget calls (unobserved exceptions) and 81 files with a catch block and no logger. These are the places where failures are hidden or leaked; fixing them needs a list and a gate, not a rewrite.

## Prompt

1) Audit script (extend tools/UiAudit or a test): list every catch that swallows (no log, no rethrow), catches too broadly, returns the exception text to the user or turns a failure into a silent default; every generic throw; every fire-and-forget task. 2) Classify: fix now (data loss, security, user-facing leak), fix with the module's next change, accept with a reason (for example best-effort cleanup). 3) Fix the highest-risk 40 first using the taxonomy of #464 and the logging of #465. 4) CI ratchet: Roslyn analyzers as errors for new code (CA1031 general catch, CA2201 reserved exception types, CA2000 disposal where useful) and a test that fails when the counts grow. 5) Report before and after in docs/audits. Sources: OWASP Error Handling Cheat Sheet (one global handler, generic user messages, no stack traces, 5xx only for server failures, monitor 5xx); Microsoft Learn ASP.NET Core error handling (UseExceptionHandler and IExceptionHandler, status code pages, ProblemDetails, error pages must not throw, start-up errors are only visible to the host); RFC 9457.

## Requirement

Done when: the audit report has counts and decisions; the 40 highest-risk places are fixed; every remaining broad catch has a logged reason; the ratchet fails a new swallowed or leaking catch.
