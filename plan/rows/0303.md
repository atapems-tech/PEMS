## Evidence

PM review 2026-10-18: a mapping file with proper tables is needed so you can tell for every customer which release branch, artifact, version number and changelog applies. It is the starting point of the customer registry (CV_REG).

## Prompt

Create a single structured file kept vendor-side (a SQLite database is recommended, exportable to Excel/CSV) with tables: customers; deployments (customer, site, Install ID, core version, module versions); releases (version number, release branch, git tag, commit, date, support period); artifacts (file name, type installer/updater/module package, checksum, signature, library path, release); changelog entries per release; deliveries (customer, artifact, date, method, status applied/failed/pending). Add small UI or import/export helpers so it can be edited and queried without a terminal; keep it consistent with the release manifest (CV_RELMAP) and the artifact library (V_ARTIFACT).

## Requirement

For any customer you can list its core and module versions, the release branch, artifact files and changelog; for any artifact you can list the customers that received it; the file can be exported to Excel and CV_REG can import it.
