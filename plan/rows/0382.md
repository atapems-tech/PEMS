## Evidence

Owner request 2026-10-27: the password chosen at the first (forced) change and at any later change must not equal the previous one. ASP.NET Identity accepts the same password again, so the forced change of a one-time or temporary password can be answered with the same value.

## Prompt

1) Study the change-password, forced-change, admin reset, recovery-code and break-glass paths and the validators in use. 2) One IPasswordValidator shared by all paths: reject the current hash and the last N hashes (Authentication__Password__HistoryCount, default 5, in every env file; key-parity test green); the one-time or temporary password counts as current. 3) Store previous hashes (new table, migration; hashes only, trimmed to N). 4) Localized message fa/en. 5) Tests per path and for inside/outside N. 6) Document in env/README.md, guideline security rule, README manual check.

## Requirement

Done when: every path that sets a password refuses the current and the last N passwords with a clear message; the setting is in every env file; tests pass; manual check and docs exist.

## Report

2026-10-27 (SCRUM-412, Claude for Hamid): one mechanism for every password path. PasswordHistoryValidator (Identity IPasswordValidator, PEMS.Web.Security) refuses a password equal to the current hash or one of the last N stored hashes (Authentication__Password__HistoryCount, default 5, 0 = off, in all six env files); PemsUserManager overrides ChangePasswordAsync/ResetPasswordAsync and stores the replaced hash in the new table PasswordHistory (migration PasswordHistory, hashes only, trimmed to N). Message in fa and en (Password_Reused). DevAdminPasswordReset uses an explicit PasswordHistoryBypass. Tests: PasswordHistoryTests 9/9 (forced first change, voluntary change, inside/outside N, trimming, token reset, hashes only, count 0, bypass, no code assigns PasswordHash); mutation (validator off) turns 6 of 9 red. Not run: the real screens in fa/en (README M-19).
