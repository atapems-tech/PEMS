## Evidence

Audit 2026-10-29: Hangfire is used (4 background-job call sites) with no retry or failure policy (no job filters, no AutomaticRetry setting), 4 Task.Run fire-and-forget calls whose exceptions nobody observes, and external dependencies (Ollama, Tesseract OCR, FTP storage, mail) without a shared timeout or circuit-breaker policy. The demo already runs without Ollama, so degraded operation is a real case.

## Prompt

1) Job policy: retry count and backoff per job kind (idempotent jobs retry, others fail fast), a failed-job state visible in the admin error list (#465) and in the health dashboard (#174), a notification to the owner role after the final failure, idempotency keys for jobs that write. 2) Replace Task.Run fire-and-forget with hosted services or queued jobs; every background path logs and observes its exceptions. 3) Resilience pipeline for outbound calls with the Microsoft resilience library (check licence and offline use, record in L_OSS): timeout, bounded retry for idempotent calls, circuit breaker, one place per dependency. 4) Graceful degradation: when AI, OCR, mail or FTP is unavailable the feature shows a clear unavailable state with the reason and the trace id, never a 500, and recovers by itself. 5) Settings in the env files; tests with a dependency that times out, fails and recovers.

## Requirement

Done when: a failing job retries by policy and then appears as failed with a notification; no fire-and-forget task remains; each external dependency has timeout and breaker settings and a degraded state; tests prove timeout, failure and recovery.
