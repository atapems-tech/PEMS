## Evidence

Audit 2026-10-29: Serilog has 1 enricher and no request logging (UseSerilogRequestLogging unused); 74 explicit error/warning calls against 174 catch (Exception); 81 files with a catch block have no logger at all. The log is a rolling file only, so an operator needs server file access to read it (the staging 500.30 was found only after reading logs/stdout over FTP). A comparable platform keeps every error in a file and in a queryable table shown in its admin app, with a reference shown to the user.

## Prompt

1) Enrichers: trace id, request path and method, user id (not name), environment, application version, tenant; request logging with status, duration and route template (no query strings with data). 2) Level policy: what is Information, Warning, Error, Critical, in one guideline paragraph. 3) Redaction: never log secrets, tokens, passwords, connection strings or document content; a destructuring policy and a test that scans log output of sample requests. 4) Error store: write errors (not all logs) to a table with message, exception type, stack (admin only), trace id, user id, route, count, first and last seen, grouped by a fingerprint so a repeating error is one row with a counter; retention setting (days) in the env files; size cap. 5) Admin UI page Errors: filter by date, level, route, user, trace id; open one; mark as seen; export for a support bundle (#174); permission-protected and audited. 6) Settings in every env/*.env file; the file log stays as the fallback when the database is down. Sources: OWASP Error Handling Cheat Sheet (one global handler, generic user messages, no stack traces, 5xx only for server failures, monitor 5xx); Microsoft Learn ASP.NET Core error handling (UseExceptionHandler and IExceptionHandler, status code pages, ProblemDetails, error pages must not throw, start-up errors are only visible to the host); RFC 9457.

## Requirement

Done when: a user's trace id finds the matching log lines and the error row in one search; a repeated error is one grouped row with a count; secrets never appear in logs (test); retention removes old rows; the page needs a permission.
