## Evidence

Follow-up of #434. References are written (DefinitionReferences) but nothing reads them: there is no 'where is this used', a page can name a definition or component that does not exist or is not published, and a definition that others use can be rolled back to a version that breaks them. The impact preview of the schema planner (#13) also needs the edges.

## Prompt

1) GET /api/v1/definitions/{id}/references (uses) and /used-by with the referencing definition, version and role. 2) At validate and publish: references to other definitions must exist and be published (components are already checked); the publisher must be allowed to read the target (design document section 6). 3) Rollback and retire: show the impact (who uses this) and refuse a change that removes something a published definition needs, with a clear problem+json. 4) Add the reference kinds the new definition kinds use (menu-target, reads, calls). 5) Conformance, service and API tests; OpenAPI snapshot.

## Requirement

Done when: the used-by list of a component or definition is returned by the API; publishing a page that points to a missing or unpublished definition gives 422 with the pointer; rolling back or retiring a definition that a published page needs is refused with the list of users; tests cover all three.
