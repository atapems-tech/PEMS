## Evidence

Request-size limits exist in 7 files without one source of truth, so the page, the application and the web host can disagree about the allowed size and the user sees a server error instead of a message. OWASP: treat file names and content types as untrusted; an allowed extension does not prove safe content.

## Prompt

1) Per-field settings: max size per file, max total size, max count, extension allowlist, MIME allowlist, image min/max width and height. 2) Server check on the upload pipeline of #183: size while streaming, extension, MIME and magic bytes (never trust the browser MIME), image dimensions, safe stored file name. 3) Derive the Kestrel/IIS request limit from the largest configured field limit (one setting in env/*.env) and show the same limit in the UI before upload. 4) Clear localised messages. 5) Per-entity or per-user quota hook.

## Requirement

Done when: a file over the limit, with a wrong extension or a mismatching content type is rejected with a clear message at the UI and at the server; the host limit follows the setting; tests cover size boundary, wrong extension and a renamed file.
