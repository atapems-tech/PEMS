## Evidence

Text and number inputs are hand-written per page (2,587 hand-written inputs in the audit) and carry no constraints. The component library needs one way to turn the constraint descriptor into HTML attributes, typing behaviour and accessible error messages.

## Prompt

1) The field components of #322 render the descriptor into HTML attributes (maxlength, min, max, step, pattern, accept, inputmode). 2) A small shared script shapes typing only (not a replacement for validation): normalise Persian/Arabic digits to ASCII, keep one decimal separator, cut decimals to the scale, show thousands separators without breaking RTL caret movement, strip disallowed characters. 3) Errors follow WCAG 2.2: text that identifies the field and says how to fix it (3.3.1, 3.3.3), not colour alone, aria-invalid on the field, message linked with aria-describedby, a summary with role alert, focus moved to the first invalid field. 4) Character counter and non-blocking hints. 5) No per-page script. 6) One shared JSON fixture file is run through the server validator and the script so both agree (parity test, see #361). Best-practice sources to apply: OWASP Input Validation Cheat Sheet (allowlist, syntactic and semantic checks, server-side authority, canonicalisation, limits before parsing, safe regular expressions); Microsoft Learn ASP.NET Core model validation; WCAG 2.2 success criteria 3.3.1 and 3.3.3; RFC 9457 problem details.

## Requirement

Done when: a field built from metadata shows the right attributes and shapes typing for every type in the catalog; error text, aria attributes and focus pass an automated accessibility check (axe) and a screen-reader spot check; the parity fixtures pass on server and script; works in RTL and LTR.
