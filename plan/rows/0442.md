## Evidence

Plan audit follow-up, owner request 2026-10-28 (after SCRUM-426 did the pagination footer). Measured: 168 views call ToString(format) (243 ISO dates, 112 date-times, 92 N0, 35 N1, 32 N3, 14 0.###, 11 0.0), about 156 views print counts, quantities or amounts, 3 script files format numbers (toFixed, Intl.NumberFormat). .NET never swaps digits itself, so a Persian page prints Latin digits today. IPemsLocale.Digits and Format exist (SCRUM-426, ADR-0008). Calendar choice (Jalali for fa) is NOT part of this task; see #367, #208 and the dates decision in ADR-0008.

## Prompt

1) Design first (small PR): one view helper and one script helper over IPemsLocale (number, integer, percent, decimal, date, date-time, count) with explicit raw escape hatch for attributes and values; decide how pages opt in (HtmlHelper or Tag Helper) and how scripts get the locale (data attribute). 2) Codemod the repeated patterns (ToString N0/N1/N3/0.###/0.0, yyyy-MM-dd, yyyy-MM-dd HH:mm) in waves by area with golden or render proof per wave (en byte-identical, fa digits only). 3) Scripts: replace toFixed and Intl.NumberFormat without a locale by the shared helper. 4) Ratchet test like the component raw-markup ratchet (#327): count of raw ToString format calls in views may only go down. 5) Exports (Excel, CSV, PDF) are covered by #371, not here. 6) Document in guideline chapter 02 what is display and what is data.

## Requirement

Done when: a Persian user sees Persian digits in every displayed number and date on the migrated pages and in the scripts that draw numbers, an English user sees Latin digits exactly as today; links, ids, form values, CSV/Excel exports and API output stay Latin; a ratchet test fails when a view formats a number or date for display without the shared helper; every wave has before/after golden or render proof.
