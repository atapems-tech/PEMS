## Evidence

Owner requirement 2026-10-28: changing a form must not crash pages or lose data, especially when the type of a field changes. The safe publish pipeline (#457) needs the actual rules for forms; the schema-change planner (#13) already plans changes of the stored entity, but a form change can be made in the definition store alone.

## Prompt

The form kind registers its compatibility rules (IDefinitionCompatibility of #457), each checked against the stored records of the entity the form writes to: 1) Field removed or renamed: data-loss (records with a value), allowed only with a mapping (hand-off to the field-migration assistant #49, planned later; until then blocked) or after the field is archived. 2) Type changed: widening is safe (integer to decimal, text length up, single to multi-select with the same options), narrowing or conversion is data-loss or breaking (decimal to integer, text to number, date to text, longer to shorter, scale/precision reduced); count the records that would not convert and show samples. 3) Select options removed or renamed while stored values use them: breaking, listed with counts. 4) Required added, min/max tightened, pattern added: NOT data-loss and not blocking for existing records (see #460: validation only applies to what the user can edit in the current state); report the number of existing records that would violate it as information ('needs attention'). 5) Calendar/format changes (Gregorian/Jalali display) are safe if the stored value is unchanged. 6) The same rules are reused by #13 for entity-level changes (one rule set, two callers). 7) A small matrix test: every (old type, new type) pair has an explicit verdict; adding a type without verdicts fails the build.

## Requirement

Done when: changing a decimal field to integer, a text field to a shorter length, removing a used field or removing a used option is reported with counts and samples and blocked until a mapping or an acknowledged exception exists; adding 'required' to a field is reported but does not block and does not invalidate stored records; the type-pair matrix test passes.
