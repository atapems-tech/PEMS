## Evidence

A cached registry (TTL + write invalidation) with ETag/gzip cured slow database access on a comparable platform; a registry change must not need a rebuild. 2026-10-28: follows the REST API standard ADR-0009 / guideline chapter 08 (#431). 2026-10-28: design in docs/architecture/METADATA_REGISTRY_DESIGN.md (ADR-0010); payload and lifecycle follow the definition envelope.

## Prompt

In-memory cache keyed by metadata version; coherent invalidation across instances. Update 2026-10-29: the per-kind stamp cache of #434 (DefinitionStamps, about 1 s) already invalidates definitions across instances. This row extends that mechanism to entity/field metadata and adds ETag/gzip for static responses; it does not build a second cache.

## Requirement

A metadata change takes effect on all instances in under 2 seconds; database load for reading metadata is near zero.
