## Evidence

Owner decision 2026-10-28 (#434 review): one permission module 'Definitions' for all kinds is fine for now, improve later. Today a role that may edit definitions may edit every kind (form, page, later menu, theme, layout); ADR-0010 section 6 asks for Definitions.<Kind>.Edit and .Publish, and a menu or theme change is more sensitive than a form change.

## Prompt

1) Permission modules per registered kind (Definitions.form, Definitions.page, ...) with View/Create/Edit/Approve (Approve = publish), created when a kind is registered (seed missing rows only, like the other modules), shown in the permission matrix with readable names. 2) The API checks the kind of the definition: the coarse gate stays, then the per-kind permission decides (a role with Definitions.page.Edit cannot edit a form; publish and rollback need Approve of that kind; list and get show only the kinds the user may view). 3) Migration of existing grants: a role that had Definitions keeps access to all registered kinds until an administrator narrows it (no lock-out). 4) allowedActions reflect the per-kind result. 5) Tests, conformance suite, OpenAPI snapshot, guideline note, ADR-0010 amendment closed.

## Requirement

Done when: a role with Definitions.page.Edit can edit a page but not a form definition (API and manager screen); publish needs Approve of that kind; existing roles keep working after the update; tests prove it.
