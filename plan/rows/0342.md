## Evidence

The owner-initiated admin reset (#343-#349) must work from the licence that a customer really holds, so the whole licence chain has to be proven first: customer request file, owner issues the licence, customer installs it, the product accepts it and the ledger shows it. Gate: every admin-password-reset row (#343-#349) can start only after #342 is Done. The separate administrator-recovery work done by Saber (second-admin reset, recovery codes, server-side break-glass) does not depend on this row and can proceed without it.

## Prompt

On a clean installation: 1) the customer licence page (#108) generates the .pemsreq request; 2) the vendor tool (#106) validates it and issues the .pemslic signed with the key from #107; 3) the licence is uploaded in the UI (and in the first-run flow #109) and activated; 4) the issue is recorded in the ledger (#341); 5) repeat for a customer whose licence was issued earlier and imported (#341). Fix what breaks, and record the run in the licence acceptance checklist (#122). Everything in this flow is done in the UI; no terminal or CLI step is required.

## Requirement

Done when: a clean install is activated with a licence issued by the vendor tool; the ledger lists that licence with its Install ID and fingerprint hash; an imported earlier licence behaves the same; the run is written in the acceptance checklist. Only then are #343-#349 unblocked.
