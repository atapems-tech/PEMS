## Evidence

Owner requirement 2026-10-28. A field is optional in version 1 and required in version 2. A record created under version 1 sits in a workflow step in someone's cartable; that user may not edit that field in this step. If the form validator checks every field, the user can never save or approve ('field X is required' for a field he cannot touch) and the flow is stuck. Validation must check only what the user can change now.

## Prompt

1) Editable set: compute, for (record, current state or workflow step, user and roles), which fields are editable (the field-permission matrix per step of the workflow studio #67 and the access rules #60, read-only and hidden fields excluded). 2) The validation engine (#356) gets an input 'editable fields' and a mode 'state-scoped': required, range, pattern, cross-field rules are evaluated only for editable fields (and for rules whose inputs are all editable); values of non-editable fields are never checked and never block a save, approve, reject or transition, even if they violate a rule added later; a rule that needs a non-editable field's value reads it as stored without judging it. 3) The same editable set drives the client script (#357) and the form runtime (#45) so server and browser agree (parity fixtures in #361 include 'newly required, not editable'). 4) A field that is NOT editable but required for the next step is enforced at the step that owns it (the step where it becomes editable), not before. 5) 'Needs attention' report: records whose non-editable fields violate the current definition are listed for administrators (and per step owner) with counts, without blocking anything. 6) Create mode (new record) still requires every editable required field; update and partial update keep the semantics of #356. 7) Tests: a record from version 1 in a step where the new required field is read-only can be saved and moved on; the same field is required in the step where it is editable; API and import paths follow the same rule; audit logs which fields were validated.

## Requirement

Done when: a user in a step where a newly required field is read-only saves and approves the record without error; the user who can edit that field must fill it; client and server give the same result; the needs-attention report lists the old records; tests prove all of it.
