## Evidence

Server-side paging above ~1,000 rows regressed twice on a comparable platform; one query contract from the start is required. 2026-10-28: REST inventory done, see docs/audits/REST_INVENTORY_2026-10-28.md and rest-inventory.csv (#432).

## Prompt

Build one /api/d/{entity} endpoint with a single query contract (page/sort/filter/search/columns) used by every list and relation list. Route shape, paging style and error format come from the REST ADR (#431), not from this row; the first version must pass the API quality gates (#436).

## Requirement

Test: 500k records, filter+sort under 500 ms; a record outside the user's access never appears in results or counts. The route and contract follow the REST API standard (#431): resource-oriented URLs instead of verbs, ETag/If-Match, RFC 9457 errors, OpenAPI.
