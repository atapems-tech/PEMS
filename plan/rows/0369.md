## Evidence

Identifiers and codes are typed and shown inconsistently (with and without spaces, dashes, Persian digits); a number-typed input cannot hold leading zeros or grouped digits, and MDN advises type=text with inputmode and a pattern for such values.

## Prompt

1) Mask and display presets from the format catalog (#366): grouping pattern, separator, case, example. 2) The PEMS.UI field renders type=text with inputmode and the pattern attribute, shows the grouped form while typing and keeps the raw canonical value in a hidden or data attribute that is submitted. 3) Paste handling: strip separators and spaces, normalise digits (#364), re-group; caret stays correct in RTL and with Persian digits. 4) Screen readers read the example format and the error, not the mask characters. 5) Server accepts only the raw form and re-validates it. 6) Component docs with examples in the catalog. Best-practice sources: W3C Internationalization (date and number formats follow the language context, avoid ambiguous numeric dates, support non-Gregorian calendars, keep localisation separate from translation); MDN notes on input type=number (locale separators and non-ASCII digits are sanitised, no pattern support, so formatted or Persian input needs type=text with inputmode); ISO 8601 for stored dates; Unicode CLDR through Intl (browser) and ICU/CultureInfo (server); OWASP: validate the canonical form, one normalisation policy.

## Requirement

Done when: a phone number, national code, IBAN and a pattern code are shown grouped, pasted in any common form and submitted raw; leading zeros are kept; caret and selection work in RTL; screen-reader and keyboard checks pass.
