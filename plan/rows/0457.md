## Evidence

Owner requirement 2026-10-28: changing a definition (form, page, menu...) must be safe. Today publish only validates the shape of the new version (#434); a change that crashes a page at render time or silently loses data (a field type changed, a field removed, an option removed that stored records use) is published and affects every user at once.

## Prompt

1) Compatibility analysis: compare the new version with the published one per kind (a kind registers an IDefinitionCompatibility next to its validator) and classify every change as safe, breaking or data-loss, with a machine-readable report (path, change, severity, affected record count where data exists, sample ids). 2) Automatic test before publish: validate, then a smoke test that renders/loads the new version with sample data and with a sample of real records of the entity (read-only, same user rights) and runs the compatibility rules of the kind; any failure blocks publish with 422 and the report. 3) Breaking or data-loss changes need an explicit acknowledgement in the publish call (and, for critical definitions, the second approver of #440); data-loss changes are blocked unless a migration mapping exists (#458, #49). 4) Publish stays one atomic switch; after it, a post-publish smoke check runs against the live definition (render and load probe through the real runtime); if it fails, the previous version is published again automatically (a new version number with change summary 'auto-rollback: <reason>', audit entry, stamp bump) and the caller gets a clear result. 5) The report is part of the validate/publish API responses and OpenAPI; settings in env/*.env (smoke timeout, sample size). 6) Tests: a deliberately breaking change is stopped before publish; a change that passes pre-checks but fails the post-publish probe is rolled back automatically; SQL Server run is a QA line.

## Requirement

Done when: a form change that removes a field or narrows a type with stored data is stopped before publish with a report; a change that crashes the runtime is rolled back automatically within the smoke timeout and the previous version is live again; a safe change publishes as before; every step is in the audit trail; tests cover all three.
