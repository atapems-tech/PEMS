## Evidence

Follow-up of #434 (definition store), design document METADATA_REGISTRY_DESIGN.md section 4. The store has Origin, ShippedVersionId and IsCustomized but nothing delivers shipped (System) definitions, so the code defaults of ADR-0011 (a database page may override a shipped page) cannot exist yet and upgrades have no rule.

## Prompt

1) Seed/importer that publishes the shipped definitions of the product (forms, layouts, pages, menus) as Origin = System with ShippedVersionId, idempotent, run at startup after migration and in the update path. 2) Upgrade rule: not customised -> the new shipped version becomes the published one; customised -> the customer's version stays and the new shipped version is stored as a draft with an 'upstream changed' flag and a diff. 3) Reset to shipped = republish the shipped payload as a new version. 4) Decide the merge question (design doc open question 4: manual merge enough, or a 3-way merge tool). 5) Tests incl. upgrade from a previous shipped version.

## Requirement

Done when: a shipped definition appears after a clean install and after an update; a customised one is not overwritten and shows an upstream-changed draft with a diff; reset to shipped restores it; all proven by tests (SQL Server run is a QA line).
