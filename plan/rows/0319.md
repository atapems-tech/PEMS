## Evidence

docs/design/COMPONENT_LIBRARY_PLAN.md section 4.1. Dynamic BPMS forms are metadata rendered at runtime (also for designer previews, e-mail/PDF and extension packs): that favours Razor components (DynamicComponent/HtmlRenderer); MVC interop (Tag Helpers, antiforgery inside components) is the known risk. Row #5 asked for this vertical slice but it was never run.

## Prompt

1) Build one slice in a branch: a field set with validation, a table with 1,000 rows, and a form with antiforgery and file upload. 2) Render it twice: from an MVC view and from a descriptor (FieldDescriptor/ColumnDescriptor sketch from COMPONENT_LIBRARY_PLAN.md). 3) Compare the two options on binding and validation parity, render time (record numbers), RTL, offline use, testability and loading from an extension assembly. 4) Write the ADR with the measured results and the decision; update row #5.

## Requirement

Done when: the ADR exists with the measured table and a clear decision; the contract classes compile; the decision is recorded in #5 and #320 can start. If static Razor components fail a criterion, the ADR names the fallback per component class.
