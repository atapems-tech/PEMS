## Evidence

Audit 2026-10-29 (static, PEMS.Web/Application/Persistence/Infrastructure/AI/WorkflowPlatform): 174 catch (Exception) and 36 bare catch blocks, 131 generic throw new Exception( against 8 custom exception classes (no taxonomy), 89 places that put ex.Message into a user-visible response, trace id used in 3 places. Good already: UseExceptionHandler('/Home/Error') outside Development, UseStatusCodePagesWithReExecute for pages, a request id on both error pages, problem+json for /api (guideline 08). The 500.30 diagnosis of the staging deploy (2026-10-25) showed a start-up failure is invisible to users and to the pipeline until someone reads logs/stdout on the server. A comparable platform has one error handler, a sanitised message in production and a uniform envelope, but trace ids that differ between browser and server.

## Prompt

1) Exception taxonomy in PEMS.Application: NotFound, Conflict (state, concurrency, unique violation), Validation (#356), Forbidden, Unavailable (dependency down), Unexpected; one mapping table to HTTP status and message key; replace generic throw new Exception. 2) One IExceptionHandler and problem details writer for MVC and API (reuse ApiProblem from #435; pages render the localised error page with the same codes). 3) Trace id: the W3C trace id is the user-visible reference everywhere (error page, toast, response header, every log line, support bundle #174). 4) Map EF/SQL errors: unique 2601/2627 to 409 with a field message, deadlock 1205 and timeouts to 503 with a retry hint, concurrency to 409. 5) Localised pages for 401, 403, 404, 409, 429, 500, 503 from one template; error pages cannot throw. 6) Start-up failure: catch host start-up exceptions, write a readable single-file report (logs/startup-error.txt, no secrets), serve a minimal static maintenance page with the reference, and let the pipeline health check print it (builds on #385). 7) Replace user-visible ex.Message with taxonomy messages and keep the detail in the log. Sources: OWASP Error Handling Cheat Sheet (one global handler, generic user messages, no stack traces, 5xx only for server failures, monitor 5xx); Microsoft Learn ASP.NET Core error handling (UseExceptionHandler and IExceptionHandler, status code pages, ProblemDetails, error pages must not throw, start-up errors are only visible to the host); RFC 9457.

## Requirement

Done when: every unhandled and mapped exception returns the same shape in the user's language with a trace id; no stack trace, SQL text, path or ex.Message reaches a user in Production (tests scan responses); the taxonomy table is documented; a forced start-up failure produces the readable report and the maintenance page.
