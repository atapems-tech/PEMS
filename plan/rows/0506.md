## Evidence

Owner request 2026-11-05: a UI library "dispatcher-like" door linked to the components (named component registry after research, ADR-0013), and the code links to it; the code graph should show it. Audit 2026-11-05: the registry (`IPemsComponentRegistry`, 26 keys) and the renderer exist and the dynamic path (`PemsDescriptorHost`, #387/#438) uses them by key, but of 60 `pems-*` tag helpers only 13 render through the registry, 2 are parts and 47 write their own markup; component keys were string literals in the registry only, so the graph showed views -> tag helper and never a component. Nothing stopped new tags from bypassing the registry.

## Prompt

Phase 1 (this task, one PR): ADR-0013; `UiKeys` constants as the one vocabulary; `[PemsFacade(...)]` on every `pems-*` tag helper (Component, Part, Direct); `UiRegistryDriftTests` (every tag helper declares its facade, a Component facade names a registered key and really renders that component, `UiKeys` equals the registry, the registry uses the constants, Direct facades never exceed a baseline that only goes down); graphify links (a node per key, edges tag helper -> component and view -> key) added by `tools/graphify/update.py`; guideline 02 section and AGENTS.md pointer. Later phases (own rows when started): convert Direct facades to registered components, batch by family (list, related, tree, nav, control), each lowering the baseline; make the page host (#438) and descriptors render only through the registry.

## Requirement

Done when: the ADR is Accepted by the owner; every tag helper has the attribute and the drift tests are green; the graph shows the key nodes; the guideline says how to add a component without drift (component, key, registry, facade, guideline row, test). SCRUM-506.
