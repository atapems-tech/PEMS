## Evidence

Follow-up of #434. The definition store has only a REST API: nobody can see, compare, publish or roll back a definition without a REST client. Kinds without their own designer (and administrators checking any definition) need one generic screen. The generic audit no longer stores the payload text, so the version history with a diff is the only readable history.

## Prompt

An Administration page (list page, detail page with tabs: versions, draft, used by) using PEMS.UI components only and the /api/v1/definitions API as its only data path: filter by kind/app/state, version history with status, hash, who and when, a payload diff between two versions (JSON-aware, readable in fa and en), the open draft with validation errors by pointer, buttons by allowedActions (validate, publish, discard, roll back, create draft), export and import with the package check results, 412 shown as a reload prompt. Raw JSON editing is allowed for administrators only (designers come with #44/#57/#439).

## Requirement

Done when: an administrator publishes, compares and rolls back a form and a page definition from the screen only; a stale edit shows the reload prompt; a user without the Definitions permission cannot open it; the screen passes the UI standards tests and the manual check (browser, fa and en, RTL).
