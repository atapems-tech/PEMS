## Evidence

Code-versus-plan audit 2026-10-28 (docs/audits/2026-10-28-code-vs-plan-gaps.md). The REST inventory (#432, docs/audits/REST_INVENTORY_2026-10-28.md) found 269 of 1,062 MVC actions in 48 controllers with no permission signal (only the global signed-in requirement applies), three state-changing GET requests (Culture/SetCulture anonymous, LetterCartable/Settings, Theme/SetTheme) and no task to review them. The review was suggested at the time but never planned; the new API has a gate (#436), the old pages do not.

## Prompt

1) Review each of the 269 actions (list in docs/audits/rest-inventory.csv, permission = none; biggest: LetterCartable 21, EngineeringDocuments 19, Letter 17, QC 17, Instrument 13, PartCatalogueRequest 12, MOC 12, DCC 10, MDB 10): decide per action 'signed-in is enough (record why)', 'needs a module permission' (add the HasPermission check or policy and the permission-matrix row) or 'row-level rule'. Controllers that are all-none first (AI, AIInsights, AISearch, Asset, ChatAssistant, DCC, DocumentRegister, DocumentRevisions, ImportCenter, Intake, KnowledgeBase, LetterCartable, LetterTemplate, MDB, MOC, MechanicalEquipment, Meeting, MyWork, Notification, Projects, QC, SearchApi, SparePart, Tag, TechnicalQuery). 2) The three state-changing GETs become POST with antiforgery (or are justified: a culture or theme switch) and keep their links working. 3) A gate (extend rest_inventory --check or an xUnit reflection test): a new MVC action without [Authorize], a permission check, [AllowAnonymous] or an entry in a reviewed allow-list fails the build. 4) Regression tests for every action that gains a permission (a user without it gets 403). 5) Role defaults so no sidebar link ends in a 403 page (rule 21-C), seeded without overwriting manual settings. Update 2026-10-29: permission checks are mixed (HasPermissionAsync about 522 uses, RequirePermission 22, MenuAccess 33, AuthorizeForRolesAsync 32, IsInRole 14). While reviewing, move each action to the one mechanism chosen in #20/#60 and record it in the allow-list; do not add a sixth style.

## Requirement

Done when: every action has a recorded decision; the 269 are either protected or listed with a reason in the allow-list; the three GETs no longer change state; the gate fails on a new unprotected action; tests prove the new 403s; the sidebar still works for the default roles.
