## Evidence

Validation in PEMS today is thin and scattered: 260 entities but only 26 [Required] and 45 [MaxLength] attributes in 28 files, no [Range], [StringLength] or regular-expression rule anywhere, no validation library, ModelState.IsValid is checked in 8 controllers, and 64 of 65 plain text inputs in the views have no maxlength. 136 decimal properties exist but only 110 precision mappings, and the application logs 'No store type was specified for the decimal property' at start (for example SparePart.QuantityOnHand, ReorderPoint, WorkOrder.DowntimeHours), which silently truncates values.

## Prompt

1) Write an audit script (extend tools/UiAudit or a test) listing: string properties without a maximum length or with nvarchar(max) that should be bounded; decimal properties without explicit precision and scale; numeric and date properties that need a range (quantities, percentages, years); controllers that write without ModelState or a validator; inputs in views without maxlength/min/max/step/inputmode. 2) Fix the highest-risk 30 first (money, quantities, identifiers, document numbers) with a migration where the column changes. 3) Add a test that fails when a new string property has no maximum length (unless marked unbounded) or a new decimal has no precision. 4) Report counts before and after in docs/audits.

## Requirement

Done when: the audit report exists with counts; every decimal has explicit precision and the start-up warnings are gone; the 30 highest-risk fields are fixed; the ratchet test is in CI.
