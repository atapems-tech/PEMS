## Evidence

A direct API call, an import or a bulk write bypasses whatever the page checks, and PEMS has no single validator to call. Validation must be authoritative on the server; the client only improves feedback. 2026-10-28: a JSON Schema validator (LateApexEarlySpeed.Json.Schema) already validates component options in PEMS.UI (#433); reuse it for definition payloads (ADR-0010).

## Prompt

1) Check libraries first (FluentValidation, JSON-schema validators) and record the licence in row L_OSS; custom code only with a stated reason. 2) Implement a validator in the engine layer with a dispatch table by field type (a new constraint is a new case, never a second parallel function): input = field descriptors + record + mode; create requires every required field, update checks only the keys present so an omitted key never means 'clear it'. Whitespace-only text counts as empty for required. 3) Return all violations (field, constraint code, message key, parameters), not only the first, capped by a setting (ASP.NET Core defaults to 200 errors and depth 32; set explicit limits). 4) Call it from one place in the generic CRUD pipeline and from static modules through an adapter (DataAnnotations and IValidatableObject keep working). 5) Messages resolved through the localisation resources (fa/en). 6) Validation never replaces authorisation, parameterised queries, output encoding or HTML sanitisation (OWASP). 7) Unit tests per type and constraint. Best-practice sources to apply: OWASP Input Validation Cheat Sheet (allowlist, syntactic and semantic checks, server-side authority, canonicalisation, limits before parsing, safe regular expressions); Microsoft Learn ASP.NET Core model validation; WCAG 2.2 success criteria 3.3.1 and 3.3.3; RFC 9457 problem details. Update 2026-10-28 (#460): add a validation mode 'state-scoped' with an input 'editable fields' (computed from the record's current state/step, the user and the roles): only editable fields are judged; non-editable fields never block a save or transition even if a later definition made them required; the descriptor/constraint set is unchanged, the scope is a parameter.

## Requirement

Done when: every write path of the generic engine calls the validator; a request that bypasses the UI is rejected with the full error list; partial updates never clear omitted fields; messages come in the user's language; the error and depth limits are settings; tests cover each type.
