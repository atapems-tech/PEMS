## Evidence

Hand-written patterns for e-mail, phone and identifiers are the usual source of false rejections and of values that look valid but are not. OWASP: use a maintained library for e-mail and verify mailbox ownership separately; the local market also needs checksum rules (national code, IBAN mod 97) and Jalali calendar validity.

## Prompt

1) Check libraries first and record their licences (e-mail: the framework mail address parser; phone: a maintained E.164 library; IBAN: ISO 13616 mod-97). 2) Implement the Iranian rules as validators: ten-digit national code with its check digit, mobile number with accepted prefixes and normalisation to one stored form, postal code, economic code, legal-entity id. 3) Jalali date validity including leap years and conversion to the stored Gregorian date. 4) Currency fields: rial and toman scale, no floating point, decimal(18,2) style precision from #355. 5) Package them as a validator pack loaded through the extension SDK (#94) so other locales can add theirs. 6) Message keys in fa/en. 7) Tests with real valid and invalid samples.

## Requirement

Done when: each validator accepts documented valid samples and rejects documented invalid ones, including checksum failures and non-existent Jalali dates; the pack loads through the extension point; e-mail and phone use a maintained library.
