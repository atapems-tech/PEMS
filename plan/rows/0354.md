## Evidence

PEMS.Persistence.dll is 29 MB, mostly ~120 migrations with their designers and the model snapshot, so every change to a data-layer service re-uploads all of it to demo and staging (difference upload).

## Prompt

Follow the EF Core guidance for a separate migrations project: new project PEMS.Migrations (references PEMS.Persistence) holds the migration files, the snapshot and the design-time factory; the context defaults its MigrationsAssembly to it so hosts, tests and tools find the migrations; Web and Tests reference the project; update the CI drift gate, deploy script, Dockerfile, solution and every documented dotnet ef command.

## Requirement

Done when: dotnet build and the migration/deployment tests pass; the drift gate runs with --project PEMS.Migrations; PEMS.Persistence.dll no longer contains migrations and a change in a Persistence service leaves PEMS.Migrations.dll byte-identical; docs and guideline use the new command.

## Report

2026-10-25: migrations moved to PEMS.Migrations (239 files git-mv'd); PEMS.Persistence.dll 29 MB -> 6 MB, PEMS.Migrations.dll 23 MB stays byte-identical when only data-layer code changes (verified with DebugType=none); drift gate, deploy.ps1, Dockerfile, docs updated; migration tests 10/10 on a real SQL Server and 65/65 database-free tests pass.
