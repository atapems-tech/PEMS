## Evidence

Validation in PEMS today is thin and scattered: 260 entities but only 26 [Required] and 45 [MaxLength] attributes in 28 files, no [Range], [StringLength] or regular-expression rule anywhere, no validation library, ModelState.IsValid is checked in 8 controllers, and 64 of 65 plain text inputs in the views have no maxlength. Dynamic forms need one declarative description of the rules per field type before any engine or UI is built. Rule-builder row #46 covers user-defined rules; this row defines the built-in constraints every type carries. 2026-10-28 plan audit: dependency/milestone corrected (see docs/audits/2026-10-28-dynamic-restful-audit.md).

## Prompt

1) For every type in #11 list its constraints. Text: required, min/max length, pattern (named presets: code, e-mail, phone, national id), allowed characters, allow digits. Number/decimal/money: min, max, strict range, step, integer only, allow negative, allow zero, scale and precision. Date/date-time: min/max date, relative window (not in the past, not in the future, within N days), Jalali-aware, time zone. Boolean: must be true. Select/multi-select: membership, min/max selected. Lookup/user: existence, active only, scope. File/image: max size per file and in total, count, extensions, MIME, dimensions. Rich text: max length of the text after sanitisation. JSON: schema. Computed/auto-number: read-only. 2) For each constraint: default, hard (blocks the save) or advisory (hint only), message key (fa/en) and parameters. 3) Define the versioned validation object stored in the metadata registry and which constraints the physical column must also enforce (length, precision, scale) so metadata and storage cannot disagree. 4) Cross-field and semantic rules (end after start, total equals sum) use the rule builder of #46 and the expression engine of #15. 5) Persian/Arabic digit normalisation and decimal separator rules (see #364). 6) Write docs/architecture/FIELD_VALIDATION_CATALOG.md and an ADR. Best-practice sources to apply: OWASP Input Validation Cheat Sheet (allowlist, syntactic and semantic checks, server-side authority, canonicalisation, limits before parsing, safe regular expressions); Microsoft Learn ASP.NET Core model validation; WCAG 2.2 success criteria 3.3.1 and 3.3.3; RFC 9457 problem details.
