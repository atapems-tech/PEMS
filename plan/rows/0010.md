## Evidence

PEMS has no general App/Entity/Field registry (audit E1/E2). The proven pattern is that everything is a database row, not code. 2026-10-28: design in docs/architecture/METADATA_REGISTRY_DESIGN.md (ADR-0010); payload and lifecycle follow the definition envelope.

## Prompt

Design and build the metadata model (App, Module, Entity, Field, Relation, OptionSet, View, Form, Menu, StatusSet) with Draft/Published/Retired states. Update 2026-10-29 (task-and-code consistency audit): the generic envelope already exists (#434, ADR-0010: Definitions, DefinitionVersions, DefinitionReferences, DefinitionStamps, lifecycle Draft/Validated/Published/Retired, rollback, package, per-kind stamp cache). This row must NOT build a second set of version tables. It registers the kinds app, module, entity, option-set and entity-extension (plus relation and status-set payloads) on that envelope through IDefinitionKind (see #451 for the kind checklist), using the field types of #11.

## Requirement

A sample entity is created, published and used for CRUD purely through metadata rows (no new C# code); metadata changes apply without build/redeploy.
