## Evidence

ADR-0002 chose Razor with the designers as embedded JavaScript components; ADR-0009/0011 make them ordinary clients of the definition API. Without one shared client, each designer (#44 forms, #57 views, #20 menus, #439 pages, the definition manager #449) would re-implement ETag/If-Match, the antiforgery header, error mapping and save behaviour, and get the 412 case wrong differently.

## Prompt

A small offline JavaScript module in PEMS.UI (wwwroot, no CDN, no framework dependency) used by all designers: typed calls for list/get/draft/save/validate/publish/rollback/export/import; keeps the ETag of the last read per resource and sends If-Match; reads the antiforgery token from the page and sends X-CSRF-TOKEN; maps problem+json errors (pointer, code, message) to field messages and to a summary; on 412 raises one standard 'changed by someone else' event with reload and compare; draft autosave with debounce and a saved/unsaved/conflict state; retries only safe reads; Idempotency-Key on creates; fa/en texts through the PEMS.UI localisation. Browser tests with the pre-installed Playwright against a stub server for 200/412/422/401/403; documentation of the events in the component catalog (#326).

## Requirement

Done when: a sample designer page created only with the client saves a draft, shows a 422 pointer next to the right field, handles a 412 with the standard dialog and survives a 401; the module has no dependency on a CDN; tests pass in the browser run and the guideline names it as the only way designers call the definition API.
